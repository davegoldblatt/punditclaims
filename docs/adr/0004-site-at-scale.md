# 0004 The site at 11,000 claims

Date: 2026-10-28. Policy 2026-10-28.7 (the screen).

The register grows from about 40 claims to about 11,000, and about 40 percent are screened out: both providers found that public evidence could not settle them. Cloudflare Pages takes at most 20,000 files per deployment and 25 MiB per file. This record amends 0003 where they differ.

1. One built file per claim. The claim page shows its current assessment, at the anchor `#assessment-<id>`. Only versions the claim page does not show (replaced or withdrawn ones) get a page of their own. When a shown assessment is later replaced, the claim page keeps the same anchor on its history entry, which links to the new version page, so a citation stays valid. Per-claim share images and per-claim JSON files are gone; claim pages use the site's share image.
2. The register shows one group at a time: the claims checked against evidence first (on the home page and each person's page), then supported, contradicted, mixed, unresolved, not yet due, and the claims that can't be checked. Each group is split into static pages of 100 rows (`/register/<group>/<n>`, `/people/<id>/<group>/<n>`), with numbered links. Filters and search inside a list run only when the whole group fits on one page; on a longer group they would see one page and mislead, so they are left out. `/changes` is split the same way, 200 to a page. The feed carries the newest 200 changes.
3. One page per source post (`/posts/<host>/<path>`) lists every claim recorded from it, in the order of the post, with its outcome and the words from that post, and the held records from the same post.
4. Pagefind indexes the post pages, the method, and the about page, not the claim pages. Each claim on a post page is a section with the anchor `c-<claim id>`; the search page turns each matching section into a result that links to the claim page. One index entry per post keeps the index under 1,300 files at 11,000 claims, where one per claim would have doubled the file count.
5. The JSON exports are split into parts of 1,000 claims. `/api/release.json` holds every manifest field except the claims, plus the list of parts; joining the parts' claims arrays rebuilds the manifest and its digest. `/api/claims.json` lists the parts of the claims export.
6. `not_adjudicable` reads "Can’t be checked". A screened-out claim says it was not checked against evidence, lists the screens' reasons, and its AI note says which model extracted it, which models screened it, and that code composed the text with no separate final-text check.
7. `scripts/check-dist.ts` fails above 19,000 files or any file over 25 MiB, and recomputes the groups, pages, post pages, changes pages, search anchors, and export parts from the manifest. `npm run build:scale` builds a synthetic release of 11,000 claims (`PC_FIXTURE_SCALE` sets the size) in the expected proportions. Measured on 2026-10-28: about 23 seconds for the whole build, 13,999 files, largest page 233 KiB (`/held`), largest file 5.1 MiB (one export part).
